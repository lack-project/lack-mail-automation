# AI Usage Info

## Sinn der Library

`lack/mail-automation` verarbeitet Mailbox-Aenderungen auf Basis von
`phore/mail-client`. Fuer neue inhaltsbasierte Workflows ist der komplette
beobachtete Mailverlauf der fachliche Zustand; fachliche Tag-/Flag-State-Machines
oder vorab definierte Mail-Klassifizierungstypen sind nicht erforderlich.

## Content-driven API

`MailAnalyzer` extrahiert Mailtext und unterstuetzte Anhaenge und speichert
chronologische Mailtexte plus Anhang-Zusammenfassungen. Es gibt keine
Mail-/Attachment-Classifications in dieser API.

Eine fachliche Aktion ist bevorzugt eine invokable Klasse mit
`#[OnMailAction(...)]`. `condition` ist eine natuerliche AI-Bedingung.
`when` ist optional und nur ein deterministischer Vorfilter; es kann ein
Methodenname am Objekt oder ein statischer Callable wie
`[MetaLead::class, 'isSource']` sein. Der Vorfilter laeuft immer vor AI.
Ohne `condition` reicht ein erfolgreicher Guard zur direkten Auswahl.

Mehrere Aktionen gemeinsam registrieren:

```php
$automation->addMailActions([
    new InitialContact(),
    new FirstReply(),
    new UpdateProfile(),
]);
```

Der Matcher sieht den kompletten beobachteten Mailtext-Verlauf, Attachment-
Zusammenfassungen sowie die Metadaten-/Dateiinventur des Conversation-Scopes.
Er waehlt hoechstens eine Action; unklare oder unvollstaendige Verlaeufe ergeben
keinen Treffer beziehungsweise optional `actionRequired`.

## Conversation Scope

`AnalyzedMail::scope()` liefert den Thread-Scope. `scopeFor($id)` erzeugt
bewusst einen anwendungsdefinierten Empfaenger-/Kunden-Scope ueber mehrere
Threads hinweg.

Der Scope bietet `get()/set()` fuer Metadaten und
`putFile()/getFile()/hasFile()/fileModifiedAt()/files()` fuer Dateien.
`ConversationStore` ist die austauschbare Persistenzschnittstelle.
Standardmaessig verwendet `AutomationStorageConversationStore` das bestehende
AutomationStorage; mit `SqliteStorage` liegen Metadaten und Dateien damit in
derselben SQLite-Datei. Ein anderer Backend-Store kann beim `MailAnalyzer`
eingesetzt werden.

Anhaenge bleiben ueber `AnalyzedMail::getAttachments()` direkt erreichbar.
Jeder Anhang bietet Summary, Volltext, Raw-Bytes und `getRawFile()`.

Startpunkt: [examples/07-ai-classification.php](examples/07-ai-classification.php)
und [docs/direct-mail-actions.md](docs/direct-mail-actions.md).

Technische Engine-Flags `processed`, `error`, `actionRequired` bleiben als
Retry-/Verarbeitungsmechanik bestehen, sind aber kein fachlicher
Konversationsstatus.
