# AI Usage Info

## Sinn der Library

`lack/mail-automation` verarbeitet Mailbox-Änderungen zustandsbehaftet auf Basis von `phore/mail-client`, löst Kontakte auf und führt registrierte Automationsregeln aus.

## Bevorzugter API-Stil

Für normalen Anwendungscode und Beispiele ist die deklarative Registrierung über PHP-Attribute zu bevorzugen: Funktionen oder öffentliche Methoden verwenden `#[OnFolderAutomation(...)]` und werden über `MailAutomation::addRules()` registriert. Die programmatische API mit `onFolder(...)->addAutomation(...)` soll nur verwendet werden, wenn Framework-, Integrations- oder Add-on-Code dynamisch Regeln aufbauen muss oder wenn ausdrücklich genau die programmatische Registrierungs-API entwickelt, getestet oder demonstriert wird.

## Logging

`MailAutomation` verwendet `phore/log` ab Version 3.0.0. Im Konstruktor kann optional ein `Phore\\Log\\PhoreLogger` übergeben werden; ohne expliziten Logger wird der globale `PhoreLogger::GetInstance()` unter dem Scope `mailAutomation` verwendet.

Jeder `MailContext` stellt den aktuell gültigen Logger über `$context->logger` bereit. Handler verwenden ihn für diagnostische oder fachliche Ausgaben statt `echo`, `print` oder eigener Debug-Ausgabe. Der Logger trägt bereits den aktuellen Message-/Automation-Kontext und kann bei Bedarf weiter gescoped werden, zum Beispiel mit `$context->logger->scope('customer')->info('Route contact {} to {}', [$contactId, $target]);`.

Die internen Synchronisations-, Regel- und Action-Schritte der Automation werden auf Debug-Level protokolliert und können zentral über die Log-Level- beziehungsweise Scope-Konfiguration von `phore/log` ein- oder ausgeblendet werden.
