# AI Usage Info

## MailContent

\`MailAnalyzer::analyze()\` returns
\`Lack\MailAutomation\Content\MailContent\`. \`MailContent\` extends
\`Phore\AiHarness\Content\AiContent\`, so the mail itself owns the AI context
used by matching and business actions.

The prepared context starts with a compact chronological conversation summary.
Complete historic mail bodies and supported attachments are registered as
additional AI Harness content objects. The current mail body is the
\`MailContent\` source itself.

Use the inherited content-query API when a task needs a specific attachment:

\`\`\`php
$result = $mail->ai_query_content('Which document is the CV?');
$document = $result->first();
\`\`\`

\`getAttachments()\` returns AI Harness document specializations directly,
including \`AiImage\`, \`AiMarkdown\` and \`AiText\` when the MIME type is
supported.

## Actions

A business action is an invokable class with \`#[OnMailAction]\`. Prefer a
natural-language \`condition\` that describes the complete business decision.
The matcher evaluates all conditions against the same bound MailContent context
and selects at most one action.

\`\`\`php
#[OnMailAction(condition: 'The applicant asks to update the profile.')]
final class ProfileAction
{
    public function __invoke(MailContent $mail, MailContext $context): MailAction
    {
        return $mail->ai_reply(
            new PromptFile(__DIR__ . '/_prompts/reply.md'),
        );
    }
}
\`\`\`

\`when\` remains available as an optional deterministic library guard, but
application routing that can be decided from the mail and conversation should
normally stay in the AI condition rather than private/static classification
helpers.

## Directory convention

Keep application actions in numeric ten-step directories such as
\`10-meta-lead\`, \`20-applicant-reply\`, \`30-profile\`. Put the action PHP
file directly in that directory and supporting prompts below \`_prompts/\`.
The underscore intentionally marks \`_prompts\` as non-namespace support data.
Numeric directories should use Composer classmap autoloading.

## Mail generation

\`MailContent\` provides:

- \`ai_reply()\` for replies;
- \`ai_mail()\` for new mail;
- \`ai_forward()\` for forward-style mail;
- \`reply()\` for a direct reply whose attachments are AI Harness
  \`AiDocument\` objects.

\`ai_mail()\` accepts a fixed recipient or \`null\`. With \`null\`, the trusted
business prompt must derive the recipient from the conversation; the resulting
address is syntax-validated before the action is scheduled.

## Conversation scope

\`scope()\` returns the thread scope. \`scopeFor($id)\` creates an
application-defined scope across threads. \`ConversationStore\` remains the
persistence interface and the default implementation stores metadata and files
through the existing SQLite-backed \`AutomationStorage\`.

Start with \`examples/07-mail-content-actions.php\` and
\`docs/direct-mail-actions.md\`.
