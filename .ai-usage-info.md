# AI Usage Info

## MailContent: die zentrale API

`MailAnalyzer::analyze()` liefert `Lack\MailAutomation\Content\MailContent`.
Das Objekt ist selbst ein `Phore\AiHarness\Content\AiContent` und traegt den
vorbereiteten AI-Context fuer die aktuelle Mail und den gesamten beobachteten
Thread.

Der Context enthaelt zuerst eine kompakte chronologische Zusammenfassung.
Vollstaendige historische Mailtexte und unterstuetzte Anhaenge sind als weitere
AI-Content-Objekte registriert. Die aktuelle Mail ist selbst ein Content-Block.

Wie bei anderem `AiContent` besitzt die Mail eine stabile ID, Aliasse und
Instructions. Eigene Werte koennen beim Erzeugen von `MailContent` angegeben
werden; ohne Angabe verwendet die Mail `mail:<message-id>` sowie die Aliasse
`mail` und `current-mail`.

```php
$mail->getId();
$mail->getAliases();
$mail->getInstructions();
```

Fuer semantische Auswahl von Dokumenten oder Anhaengen wird die geerbte
Content-API verwendet:

```php
$result = $mail->ai_query_content(
    'Welches PDF ist der zuletzt an den Bewerber gesendete Lebenslauf?',
);

$pdf = $result->first();
```

## AI-Routing

Eine fachliche Automation ist eine invokable Klasse mit genau einer
`#[OnMailAction(condition: ...)]`-Bedingung. Diese Bedingung beschreibt in
natuerlicher Sprache, wann die Action ausgefuehrt werden soll. Der Matcher
entscheidet aus Mail, Verlauf und Content-Kontext hoechstens eine Action.

Es gibt fuer `OnMailAction` keinen separaten `when`-Guard. Deterministische
private oder statische Klassifizierungsfunktionen gehoeren nicht in den
normalen fachlichen Routing-Pfad.

```php
#[OnMailAction(
    condition: 'Dies ist die erste Antwort des Bewerbers auf unsere Erstkontakt-Mail.',
)]
final class RequestCvDetails
{
    public function __invoke(MailContent $mail): MailAction
    {
        return $mail->ai_reply(
            new PromptFile(__DIR__ . '/_prompts/request-details.md'),
        );
    }
}
```

Alle zusammengehoerigen Actions werden einmal registriert:

```php
$automation->addMailActions([
    new InitialContact(),
    new RequestCvDetails(),
    new BuildCvDraft(),
    new ForwardApprovedCv(),
]);

$automation->run();
```

## Mail erzeugen

Die drei normalen AI-Mailoperationen arbeiten auf demselben gebundenen Context:

- `ai_mail($prompt, to: null, ...)` erzeugt eine neue Mail. Wenn `to` null
  ist, muss der vertrauenswuerdige Prompt den Empfaenger aus dem Kontext
  bestimmen.
- `ai_reply($prompt, ...)` erzeugt eine Antwort auf die aktuelle Mail.
- `ai_forward($to, $prompt, ...)` erzeugt eine neue Forward-Mail an einen
  expliziten Empfaenger. Subject und Anhaenge koennen explizit gesetzt werden;
  ohne Subject darf die AI anhand des Prompts eines erzeugen.

Prompts koennen Strings, `PromptFile` oder Arrays daraus sein:

```php
return $mail->ai_mail([
    new PromptFile(__DIR__ . '/_prompts/initial.md'),
    'Use the applicant email address and salutation from the lead mail.',
]);
```

Anhaenge werden direkt als `AiDocument`-Objekte uebergeben:

```php
return $mail->ai_reply(
    new PromptFile(__DIR__ . '/_prompts/review.md'),
    attachments: [$pdf],
);
```

## Conversation und Verlauf

`conversationSummary()` liefert den kompakten chronologischen Index des
Threads. `getHistory()` liefert die bereits beobachteten Nachrichten und
`getConversationAttachments()` die aktuellen und historischen Anhaenge.
Damit kann eine Action aus dem kompletten bisherigen Verlauf entscheiden,
welcher Schritt als naechstes erforderlich ist.

`scope()` und `scopeFor($id)` stellen zusaetzlichen persistenten
Anwendungszustand bereit. Der Standard-`ConversationStore` verwendet die
bestehende SQLite-`AutomationStorage`.

## Spezialfunktionen

Tags, Metadaten, Contacts, manuelle Flags, Ordnerregeln und gefilterte
Mail-History bleiben verfuegbar, sind aber fuer den normalen AI-gerouteten
Ablauf nicht erforderlich. Verwende sie nur, wenn eine Anwendung bewusst
zusaetzlichen technischen oder persistenten Zustand ausserhalb des
Conversation-Contexts benoetigt.

Siehe `examples/07-mail-content-actions.php` und
`docs/direct-mail-actions.md` fuer den kompakten End-to-End-Ablauf.
