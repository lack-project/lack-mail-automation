# AI Usage Info

## Standard application flow

Use `MailAutomation::fromConfig(new MailAutomationConfig(...))` in a bootstrap
file and run the package CLI. Applications should not implement mailbox sync,
locking, cursor handling, Sent indexing or automation-flag handling themselves.

```php
return MailAutomation::fromConfig(
    new MailAutomationConfig(
        mailbox: dirname(__DIR__) . '/mailclient.yaml',
        storage: __DIR__ . '/run/mail-automation.sqlite',
        actionsDirectory: __DIR__ . '/actions',
        aiOptions: $aiOptions,
    ),
);
```

The default CLI bootstrap path is `automail/bootstrap.php`.

```bash
vendor/bin/lack-mail-automation.php run
vendor/bin/lack-mail-automation.php run --dry-run
vendor/bin/lack-mail-automation.php run --mail-id '<mail-client-id>'
```

`run` owns the process lock and standard Sent -> Inbox cycle. `--mail-id`
reprocesses exactly one message without moving a folder cursor. Mailbox folder
names and the `processed`, `error`, `actionRequired` keywords come from
`phore/mail-client`'s `MailboxConfig`.

## Mail model

Observed messages are `AiMail`. AI-generated new messages, replies and
forwards are `AiMailDraft` instances extending `AiMail`. Only drafts expose
outbound mutation and delivery methods.

## Routing

Use invokable action classes with
`#[OnMailAction(condition: ..., priority: ...)]`. The complete semantic rule
belongs in `condition`; higher numeric priority is only a tie-breaker.

Low-level registration and manual folder APIs remain library integration APIs,
not application bootstrap boilerplate.
